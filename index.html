重要な精度補足

action_horizon = 40 はAction Headが扱う最大tensor horizon。各Embodimentの有効horizonは ModalityConfig.action.delta_indices の長さで決まり、40未満でもよい。例えば公式の新規Embodiment例には16-step構成が存在する。よって「N1.7は常に40個すべてを意味のあるActionとして出す」と固定的に説明しない。

Action Horizonはモデルが予測する未来範囲。Execution Horizonは、その予測のうち次の再推論まで何step実行するか。後者はAction Headの固定値ではない。

KEY INSIGHT

モデルが学ぶのは「この途中状態 xₜ なら、Action tensorをどちらへどれだけ動かすべきか」というvelocity field。完成Actionを1回で直接回帰する構造ではない。

現行コードの核心 
actions = action_input.action
noise = torch.randn(actions.shape)
t = sample_time(...)

noisy_trajectory = (1 - t) * noise + t * actions
velocity = actions - noise

action_features = action_encoder(noisy_trajectory, t_discretized, embodiment_id)
...
pred = action_decoder(model_output, embodiment_id)
pred_actions = pred[:, -actions.shape[1]:]

action_loss = mse_loss(pred_actions, velocity, reduction="none") * action_mask

06 · INFERENCE

推論ではGTなし。Noiseから4回、自分で進む

推論開始時の actions は乱数。各integration stepでAction Encoder → DiT → Decoderを通してvelocityを得て、Euler updateする。

TRAINING
  1. GT ActionありA
  2. Noise生成ε
  3. 途中状態を作るxₜ
  4. 正解velocityを作るA−ε
  5. velocity predictionを学習MSE
INFERENCE
  1. GT Actionなし—
  2. Noiseから開始[B,40,132]

num_inference_timesteps = 4 はAction tensorを数値的に更新する回数。robotが4回動く意味ではない。robot時間軸はAction Chunkの40 timestep側。

13 · COMMON MISCONCEPTIONS

ここを間違えると全体像が崩れる

01

Actionを1stepずつautoregressive生成？

違う。 Action Headでは未来chunk全体をcontinuous tensorとして同時に扱う。

02

DiTはGaussian Noise εを予測？

現行N1.7では違う。 training targetは velocity = actions − noise。

03

Action Horizon 40なら40step全部実行？

違う。 Execution Horizonはdeployment側の別概念。さらにEmbodiment有効horizon自体が40未満の場合もある。

04

VLMがjoint angleをtoken生成？

違う。 VLMはsemantic features。continuous ActionはAction Head側。

05

全Robot共通で7DoF Action？

違う。 Action keys / dimension / relative・absoluteはEmbodiment Config依存。

06

Flow Matchingの4 step = robotが4回動く？

完全に別。 4は数値積分回数、40はActionの時間軸。

「DiffusionなのかFlow Matchingなのか」

コードdocstringには flow matching diffusion policy、コメントには denoising steps が登場。一方、実際のtraining targetはvelocity A−ε、推論はvelocityをEuler integrationする実装。したがって教材では、Flow Matchingで実装されたcontinuous-action generative policyを主語にしつつ、repository内でdiffusion / denoisingという語が併用される事実も残す。

14 · GLOSSARY + SOURCES

重要用語と検証元

VLA

Vision-Language-Action。視覚・言語をrobot actionへ接続するpolicy。

Action Chunk

未来複数stepのActionをまとめたsequence tensor。

Action Horizon

一度に予測する未来範囲。N1.7 model最大40。

Execution Horizon

予測chunkから次推論まで実行するstep数。

Flow Matching

Noise分布からdata分布へ運ぶvelocity fieldを学習する生成法。

Gaussian Noise

推論のAction tensor初期値。標準正規乱数。

Velocity Field

現在のnoisy Actionをどちらへ動かすか示すベクトル場。

DiT

Diffusion Transformer系block。N1.7ではvelocity予測表現を処理。

Euler Integration

x ← x + Δt·v の数値積分。現行configは4 step。

Timestep

Flow上の進行度。Action EncoderとDiTへ条件として入力。

Padding / Mask

異なるdimension / horizonを共通tensorへ詰め、無効領域をmask。

Embodiment

robot身体構造・action/state定義の単位。

Receding Horizon

chunk先頭だけ実行し、最新観測から再計画する運用。

RTC

前chunk overlapを新chunk生成へ取り込むReal-Time Chunking。
